## Findings

### P1-1 Habit check-off cannot be done from the keyboard
- Anchor: `apps/desktop/src/components/goals/HabitsSection.tsx:144-149`
- Rubric: §1.5, §3.6
- Screens: light `goals-habits-light.png`, dark `goals-habits-dark.png`
- What's wrong: `HabitCircle` wires `onMouseDown/onMouseUp/onMouseLeave/onTouchStart/onTouchEnd` only. Focusing the "Hold to complete Journal" button and pressing Enter then Space left the completed count at 3→3→3. `getComputedStyle(activeElement)` on focus returns `outline: none; box-shadow: none` — no focus ring either. §2.6 says habits are "checkable from the app"; today that means mouse-only, on the one surface Marco touches every morning.
- Fix: add `onKeyDown` (Enter/Space → `onToggle()` directly, no hold) and the shared `focus-visible:ring-[3px] focus-visible:ring-ring/50` classes used by `toggle.tsx:7`.

### P1-2 Goal cards and timeline rows are click-only `div`s
- Anchor: `apps/desktop/src/components/pages/GoalsPage.tsx:56-63`; `apps/desktop/src/components/goals/GoalTimeline.tsx:102-107`
- Rubric: §1.5, §3.6
- Screens: light `goals-focus-light.png`, dark `goals-dark.png`
- What's wrong: `<Card onClick>` renders a `DIV` with `tabIndex = -1` (measured); six Tabs from page load land on a header button, never a card. The timeline's left-panel rows are the same pattern. Opening a goal — the surface's only navigation — has no keyboard reach and no `j/k` equivalent like Tasks has.
- Fix: render the card body as a `<button type="button">` (or `role="button" tabIndex={0}` + Enter/Space handler) with the standard `focus-visible` ring; same for timeline rows.

### P1-3 Habit toggle is not optimistic and flashes the skeleton on every check-off
- Anchor: `apps/desktop/src/components/goals/HabitsSection.tsx:331-344, 352-365`; `apps/desktop/src/stores/goalsStore.ts:44-51`
- Rubric: §1.6, §3.6
- Screens: light `goals-habits-light.png`, dark `goals-habits-dark.png`
- What's wrong: `handleToggle` awaits `dp.habits.log()` then `await loadHabits()`; `loadHabits` sets `habitsLoading: true` first, and `HabitsSection` returns the `<Skeleton>` branch whenever that flag is true. Net effect: every check-off unmounts the four circles, shows four skeleton discs, then remounts — the opposite of "instant strikethrough + check animation". Failure path is `console.error` only; no toast.
- Fix: flip `today_completed` in the store before the call (rollback on catch with `toast.error`), and make `loadHabits` only set `habitsLoading` when `habits.length === 0`.

### P1-4 Hold-to-complete adds 500 ms of friction with no partial-credit payoff
- Anchor: `apps/desktop/src/components/goals/HabitsSection.tsx:94-118, 336`
- Rubric: §3.2 (multi-step where one-step would work); decided intent in `goals-ux-decisions.md` ("One-tap completion is the friction minimum")
- Screens: light `goals-habits-light.png`, dark `goals-habits-dark.png`
- What's wrong: The hold gesture was designed to capture 1–5 intensity, but `dp.habits.log(habitId)` is called with no intensity — the hold produces exactly the same binary log a tap would. Uncompleting is a single click (line 97-100), so the gesture is also asymmetric. Mouse-leave during the hold silently cancels with no feedback.
- Fix: single click logs at default intensity (keep hold as an optional upgrade only once `log()` takes an intensity — `NEEDS RUST → queue for Marco` for the intensity parameter).

### P1-5 Stock-palette colors painted directly instead of theme vars
- Anchor: `apps/desktop/src/components/goals/GoalTimeline.tsx:156-157` (`bg-amber-500/60`, `bg-amber-500 text-white`); `apps/desktop/src/components/goals/HabitsSection.tsx:371, 395` (`text-amber-500`); `apps/desktop/src/lib/goalStatus.ts:5-7` (`text-amber-500`, `text-blue-400`, `text-green-500`); `GoalsPage.tsx:52` and `GoalTimeline.tsx:166` (`'#f59e0b'` fallback)
- Rubric: §3.4 (hardcoded colors instead of frame theme vars), §1.4
- Screens: light `goals-timeline-light.png`, dark `goals-timeline-dark.png`
- What's wrong: 6 sites (grep) bypass `themes.css`. Measured: the "Today" pill is white on `#f59e0b` at **2.15:1** in both themes (fails 4.5:1). `text-amber-500` resolves to `oklch(0.769 0.188 70.08)` — a cool, saturated amber that does not sit in the warm ramp. `statusColor` paints Paused blue and Achieved green with the same value in light and dark. None of these adapt when the theme flips.
- Fix: route through tokens — add `--warning`/`--info` roles next to `--success` in `themes.css` (both blocks) and use `text-success` for Achieved; make the Today pill `bg-foreground text-background` (already the tooltip pair) or a dark amber with measured ≥4.5:1. `CROSS-SURFACE`: `text-amber-500` also appears in Today (`Flame` is shared).

### P1-6 `font-medium` / `font-semibold` / `font-bold` stacks instead of scale tokens

### P2-1 Progress-bar fill is the life-area/goal color, not health — color with no semantic meaning
- Anchor: `apps/desktop/src/components/pages/GoalsPage.tsx:52, 96-105`; `apps/desktop/src/components/goals/GoalTimeline.tsx:166, 196-208`
- Rubric: §1.4 (color reserved for status/priority/source/health); decided in `goals-ux-decisions.md` → "Fill color based on health: warm green / amber / coral"
- Screens: light `goals-light.png`, dark `goals-dark.png`
- What's wrong: Four saturated bars (indigo, pink, green, amber) sit at the visual center of every card and encode nothing except which chip is above them — the chip dot already carries that. The same raw hex is used in dark mode, so the bars are the brightest thing on the page in both themes. Timeline bar label text uses the same raw hex on a 20 % tint of itself: light **1.85–3.63:1**, dark **2.70–4.90:1** across the eight `GOAL_COLORS` (all but one pair fail 4.5:1).
- Fix: fill with `bg-foreground/70` (neutral) by default and a health token only when pace is behind/ahead; keep area color on the 6 px chip dot only. Timeline label → `text-foreground`.

### P2-2 Infinite `animate-pulse` on a finished goal
- Anchor: `apps/desktop/src/components/pages/GoalsPage.tsx:99`
- Rubric: §1.4 (restrained); decided "subtle pulse … once, not recurring"; craft: Motion restraint
- Screens: light `goals-light.png`, dark `goals-dark.png`

### P2-3 Motion durations bypass the tokens; `transition-all` everywhere
- Anchor: `GoalsPage.tsx:59` (`duration-150`), `:98` (`duration-500`); `GoalTimeline.tsx:202` (`duration-300`); `HabitsSection.tsx:138` (`duration-200`), `:184` (`duration-500`); `transition-all` ×9 (`GoalsPage.tsx:59, 98, 296`; `GoalTimeline.tsx:202`; `HabitsSection.tsx:138, 184, 425, 495, 612`)
- Rubric: §1.6 (ease-out motion); brief: hardcoded `duration-*` that bypass `--transition-fast/base/slow` are findings; craft: Never use `transition: all`
- Screens: light `goals-light.png`, dark `goals-dark.png`
- What's wrong: 5 hardcoded durations (150/200/300/500 ms — 500 and 300 are outside the token set) and 9 `transition-all`, none referencing `--ease-entrance`. The progress bar's 500 ms `all` transition fires on mount, so bars visibly grow from 0 on every page open.
- Fix: `transition-[width] duration-(--transition-base) ease-(--ease-entrance)` on bars; `transition-colors duration-(--transition-fast)` on hover states; `transition-[opacity,scale]` on the habit circle. `CROSS-SURFACE`: same bypass pattern in `CollapsibleSection.tsx:56`.
