## Findings (P1 first, then P2, then P3; cap 25, prefer fewer and sharper)

### P1-1 The tree cannot be driven from the keyboard
- Anchor: `apps/desktop/src/components/docs/FolderTree.tsx:208-217` (native doc row), `:241-250` (unfiled row), `:386-399` (vault note row), `:159` (New document is mouse-only)
- Rubric: §1.5, §3.6
- Screens: light `docs-tree-focus-light.png`, dark `docs-dark.png`
- What's wrong: Doc and note rows are `<div onClick>` — not focusable, no Enter/Space activation. Tabbing from the search box cycles through chevron buttons only (measured sequence: 7 × `BUTTON:""`). There is no ↑/↓ or j/k row navigation, no ←/→ to collapse/expand, and no single key for "New document". On the Tasks surface j/k already move a selection (`hooks/useTaskNavigation.ts:37`); Docs has nothing equivalent.
- Fix: Render rows as `<button>` (or `role="treeitem"` + `tabIndex`) and add a roving-focus handler for ↑/↓/←/→/Enter plus a `N` shortcut for new document, registered in `HelpPanel.tsx`. CROSS-SURFACE (pattern lives in Tasks; Docs and Inbox should share it).

### P1-2 Search results have no keyboard path
- Anchor: `apps/desktop/src/components/docs/DocsSearch.tsx:81` (only Escape handled), `:94-106` (hit buttons)
- Rubric: §1.5, §3.6
- Screens: light `docs-search-light.png`, dark `docs-search-dark.png`
- What's wrong: With results showing, ArrowDown leaves focus in the input (measured `INPUT:""`) and Enter does nothing — the user must reach for the mouse to open the hit they just typed for. The command bar's own list handles ↑/↓/Enter; the Docs search does not.
- Fix: Track an active index in `DocsSearch`, handle ↑/↓/Enter in the input's `onKeyDown`, mark the active hit with `aria-selected` and the same `bg-muted` treatment the command bar uses. CROSS-SURFACE (command bar already has this).

### P1-3 Selected and hover states are effectively invisible
- Anchor: `apps/desktop/src/components/docs/FolderTree.tsx:182` (folder row hover `bg-accent/10` only), `:214`/`:247`/`:393` (selected `bg-accent/40`), `:365` (vault folder button hover), `DocsSearch.tsx:100`
- Rubric: §1.6 (every interaction produces immediate visual response), §1.4
- Screens: light `docs-native-doc-light.png` ("Ideas" selected), dark `docs-native-doc-dark.png`
- What's wrong: `--accent` is one step off `--background` in both themes (0.96 vs 0.995 light; 0.22 vs 0.14 dark), so `bg-accent/40` measures 1.04:1 (light) / 1.06:1 (dark) against the tree background and `bg-accent/10` measures 1.01:1 in both. Doc rows at least flip text from muted to foreground on hover; folder rows (`:182`, `:365`) and the Vault header (`:271`) have no other cue, so hovering a folder produces nothing visible. The Tasks sidebar uses `bg-muted` at full opacity + `text-meta-strong` for its selected row (`ProjectSidebar.tsx:112-121`).
- Fix: Use `bg-muted` (selected) and `hover:bg-muted/50` (hover) to match `ProjectSidebar`, and add `text-meta-strong` on the selected row. CROSS-SURFACE (Tasks sidebar is the reference; Inbox should be checked for the same `accent/10` hover).

### P2-1 Read-only is stated, not shown
- Anchor: `apps/desktop/src/components/docs/VaultNoteEditor.tsx:102` (12px muted label), `:110-116` (body rendered with the identical editor surface), `apps/desktop/src/components/docs/TiptapEditor.tsx:134`, `:231`
- Rubric: §1.6 (instant feedback), §1.2 (reduce decision overhead)
- Screens: light `docs-vault-note-light.png`, dark `docs-vault-note-dark.png`
- What's wrong: The only read-only signal is "Notes are edited in Obsidian" in `text-meta text-muted-foreground` at the top-right, the dimmest text on the page ("earned attention" applied to the one fact the user needs). The body is byte-identical to the editable native view — same padding, same colors, I-beam cursor — so a click into it looks like it should place a caret and then nothing happens. Locked decision is respected; this is presentation only.
- Fix: Give the read-only body a static cue — `cursor: default`, `select-text`, a lock/`BookOpen` glyph next to the path, and move the sentence to sit with the path on the left as `Read-only · edited in Obsidian`; keep "Open in Obsidian" as the single filled action.

### P2-2 YAML frontmatter renders as a bold heading
- Anchor: `apps/desktop/src/components/docs/VaultNoteEditor.tsx:111-116` (passes raw `note.content`; the header comment at `:15-16` already documents that frontmatter becomes an `##`), `apps/desktop/src/components/docs/TiptapEditor.tsx:152`
- Rubric: §1.4 (metadata dimmer than primary content), §1.2
- Screens: light `docs-vault-note-light.png`, dark `docs-vault-note-dark.png`
- What's wrong: `type: capture tags: [inbox]` renders as a 13px/500 heading above the real H1 — metadata is the first and boldest line of every vault note that has frontmatter (most of them). It also reads as a dashed "---" horizontal rule in notes where markdown-it treats the fence as `hr`.
- Fix: Split a leading `^---\n…\n---\n` block off `note.content` before it reaches `TiptapEditor` and render its keys as a `text-label` chip row under the path line (or nothing).

### P2-3 Native doc and vault note use two different page layouts
- Anchor: `apps/desktop/src/components/docs/DocEditor.tsx:116` (`mx-auto max-w-2xl p-6`, folder badge + title input) vs `apps/desktop/src/components/docs/VaultNoteEditor.tsx:99` (`px-8 pt-6`, full-width path row) and `:110` (`px-8 py-4`)

- What's wrong: Clicking between a doc and a note shifts the content column from a centered 624px measure with 24px padding to a left-anchored 654px measure with 32px padding; the eyebrow changes from folder name to file path; the title changes from an input to an in-body H1. Same surface, two layouts.

### P2-4 Tree row height and text treatment differ from the Tasks sidebar
- Anchor: `apps/desktop/src/components/docs/FolderTree.tsx:182`, `:212`, `:365`, `:391` (`py-1` + 12px → 24.8px) vs `apps/desktop/src/components/tasks/ProjectSidebar.tsx:112` (`h-9` → 36px, `text-foreground`)
- Rubric: §3.5 (row heights outside ~32–36px), §1.4 density, cross-surface consistency
- Screens: light `docs-light.png`, dark `docs-dark.png`
- What's wrong: Docs rows are 24.8px and `text-muted-foreground` by default; Tasks project rows are 36px and `text-foreground`. Neither is on the 8px grid. The two sidebars sit in the same slot on adjacent pages and read as two different apps. ### P2-5 Delete is one hover-click with no confirm and no undo
- Anchor: `apps/desktop/src/components/docs/FolderTree.tsx:99-107` (`handleDeleteDoc`), `:109-116` (`handleDeleteFolder`), `:196`, `:221`, `:254`
- Rubric: §1.6 (feedback), cross-surface consistency (ProjectSidebar confirms inline at `ProjectSidebar.tsx:94-105`)

### P2-6 Empty state is passive and half-wrong

### P2-7 Vault section is visually subordinate to the folders it outweighs
- Anchor: `apps/desktop/src/components/docs/FolderTree.tsx:275-276` (`text-label` 11px muted "Vault" + count) vs `:187` (native folder names `text-meta` 12px foreground); `:186` (`FolderOpen` always, even collapsed) vs `:368` (`Folder` for vault folders); `:320-327` ("New folder" rendered below the vault subtree)

Native folders show an *open* folder glyph regardless of state while vault folders show a closed one, so the two halves of one tree use different icon rules. "New folder", a native-docs action, sits under the vault subtree and reads as "new vault folder".

### P2-8 Interactive elements lack semantics and names
- Anchor: `apps/desktop/src/components/docs/FolderTree.tsx:208` / `:241` / `:386` (`div onClick` rows), `:189-200` and `:220-225` (icon-only Plus/Trash with no `title`/`aria-label`), `apps/desktop/src/components/docs/DocsSearch.tsx:86` (clear button, no name), `apps/desktop/src/components/docs/DocNoteEntry.tsx:21` (delete note, no name), `apps/desktop/src/components/docs/DocEditor.tsx:186-192` (`<p onClick>` "Add a note...")

### P2-9 Focus ring is the base fallback and fails contrast
- Anchor: `apps/desktop/src/index.css:113` (`* { @apply outline-ring/50 }` is the only focus style the surface gets), `apps/desktop/src/components/docs/FolderTree.tsx:183`, `:269`, `:362`; `grep -rl focus-visible components/docs` = 0 (14 files elsewhere use it)

### P2-10 The "docs and vault" search has no shortcut, and the help panel points at a different search
- Anchor: `apps/desktop/src/components/docs/DocsSearch.tsx:78` (input, no hotkey), `apps/desktop/src/components/shared/HelpPanel.tsx:43` (`/doc` → "Search docs"), `apps/desktop/src/components/shared/CommandBar.tsx:31` (`/doc` searches native docs only)

- Screens: light `docs-search-light.png`, dark `docs-search-dark.png`

A user who reads `?` will never find vault search.
- Fix: Bind `/` (when not in an input) on the Docs page to focus `DocsSearch`, and add a "Docs" section to `HelpPanel` listing `/`, the P1-1 tree keys, and "Cmd+K `/doc` — native docs only". CROSS-SURFACE (shell: HelpPanel).

### P3-7 No reduced-motion handling
- Anchor: `apps/desktop/src/components/docs/FolderTree.tsx:184`, `:273`, `:367` (chevron `transition-transform`), `DocsSearch.tsx:99`; `grep -rn 'motion-reduce\|prefers-reduced-motion' apps/desktop/src` = 1 hit (`components/ui/button.tsx`)
