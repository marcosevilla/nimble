# Design facelift — Loop 1 plan (2026-09-22)

> **For agentic workers:** REQUIRED SUB-SKILL: `superpowers:subagent-driven-development`, one worktree per theme (`superpowers:using-git-worktrees`). Each task below points at the finding IDs in `docs/audit-findings/<surface>/2026-09-22-loop1.md`; those findings carry the `file:line` anchor, the rubric section and the fix line and are the code-level spec. Implementers read the finding, not this table, before touching a file.

**Goal:** Make the seven pages read as one designed object by fixing the five root causes every surface audit found: an imperceptible focus ring and no reduced-motion, hardcoded palette colors where semantic tokens exist, mouse-only rows and unreachable actions, urgency-performing copy and color, and seven page frames instead of one.

**Architecture:** Three stages. Stage A lands the token/keyboard foundation in one worktree and merges first, because every other theme references its tokens and its shortcut registry. Stage B runs five worktrees in parallel on disjoint files. Stage C runs after B merges and does the page-frame and motion sweep across every page, so it never fights a Stage B diff.

**Tech stack:** React 19, Tailwind v4 (`@theme` in `apps/desktop/src/index.css`, accent themes in `themes.css`), shadcn/ui base-nova, Zustand. Tests: `node --test tests/*.test.mjs` in `apps/desktop` (8 passing today). Type check = `npm run build` and `npm run build:web`.

**Spec:** `docs/ux-intent.md` (rubric) + the nine finding files under `docs/audit-findings/*/2026-09-22-loop1.md` + `docs/audit-findings/cross-cutting/2026-09-22-loop1.md`.

## Global constraints (every task)

- Frontend only: `apps/desktop/src`. No Rust, schema, sync or Tauri command changes. Anything that needs one is listed under **Queued for Marco** and is not a task.
- Locked: Cmd+K is actions-only; vault editing disabled; C1–C5 order; no streaks / "overdue" / "you've been away" copy.
- Every existing keyboard shortcut is preserved. `q` stays quick-create. Additions only.
- No new npm dependencies (natural-language dates via `chrono-node` is therefore queued, not planned).
- Tokens over literals: new colors, sizes, radii, shadows go in `index.css` / `themes.css` (warm light AND dark) and are referenced. Contrast is measured, not assumed (better-colors method; the shell audit lists the measured values).
- Reduced motion: every animation added or touched must be covered by the Stage A global rule or a `motion-reduce:` variant.
- Sentence case everywhere. Type scale = the live 8-token `@theme` set in `index.css` (label, meta, meta-strong, body, body-strong, title, display, timer). No `font-medium` stacks, no raw `text-xs/sm`.

- Verification before "done": paste `npm run build`, `npm run build:web`, `node --test tests/*.test.mjs` output, and the retaken light + dark screenshot paths under `docs/audit-findings/screenshots/loop1-after/`.

## Decisions folded into this plan (say so if you disagree)

- **Past-due dates go neutral.** Two surface audits rate the red date a P1 under §1.1; the cross-cutting agent called it a policy question. The rubric is explicit, so B2 executes it. Today keeps `text-foreground`, everything else `text-muted-foreground`.
- **Typography doc follows the CSS**, not the other way round. The 8-token live scale is what every component uses; the doc's 10-token table is the stale side.
- **Hold-to-complete stays** but a single click also completes at default intensity.
- **`?` opens help, `g`+key navigates** — both additive, both from §1.5.
