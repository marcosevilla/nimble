## Findings (P1 first, then P2, then P3; cap 25, prefer fewer and sharper)

### P1-1 Move-to-doc picker is mouse-only: Escape does not close it and focus never enters it
- Anchor: `apps/desktop/src/components/pages/InboxPage.tsx:481-485` (overlay + "Esc" label button; no `onKeyDown`, no `useEffect` key listener, no `role`, no focus move)
- Rubric: §3.6 (Escape doesn't return to previous state), §1.5
- Screens: light `docs/audit-findings/screenshots/loop1-before/inbox-movetodoc-light.png`, dark `.../inbox-movetodoc-dark.png`
- What's wrong: The picker renders a button labeled "Esc" but nothing listens for the key; verified in the harness — `Escape` leaves the picker mounted, only a backdrop click closes it. Dashboard's global Escape (`Dashboard.tsx:144-155`) only clears selection or closes detail. Focus stays on the "Move to doc" button under the overlay, so Tab order and screen readers never enter the picker.
- Fix: Render it with the shadcn `Popover`/`Dialog` primitive already used by `StatusDropdown` (Escape, focus trap, `role="dialog"` for free), or add a `keydown` listener for Escape and `autoFocus` the first doc button.

### P1-2 Row actions are unreachable without a mouse and undiscoverable
- Anchor: `InboxPage.tsx:421` (`opacity-0 transition-opacity group-hover:opacity-100`, no `group-focus-within`), `:422-435` (no shortcut hint on either action), `SelectionCheckbox.tsx:33-47` and `StatusDropdown.tsx:124-139` (icon-only buttons with no `aria-label`)
- Rubric: §1.5 (every common action has a single-key shortcut; shortcuts discoverable), §3.6 (common action without a single-key shortcut)
- Screens: light `.../inbox-action-focused-light.png`, dark `.../inbox-action-focused-dark.png` (the "Convert to task" button holds focus; the cluster is invisible in both)
- What's wrong: Measured: the action cluster stays at `opacity: 0` while a button inside it is focused, so a keyboard user Tabs through two invisible controls per row. There is no `j/k` row navigation, no `Enter` to open the focused row beyond Tab-hunting the title button, and no single key for convert, move or dismiss. The checkbox and status trigger announce as unnamed buttons.
- Fix: Add `group-focus-within:opacity-100` today; then a keyboard layer for the list (`j/k` move, `Enter` open, `t` convert, `m` move to doc, `d` dismiss) with `<kbd>` hints on the buttons and entries in `HelpPanel.tsx`; add `aria-label` + `aria-pressed` to `SelectionCheckbox` and `aria-label="Status: {label}"` to the status trigger. `CROSS-SURFACE`: 8 sites app-wide use `group-hover:opacity-100` with zero `focus-within` equivalents (Tasks `TaskItem.tsx:158`, `SelectionCheckbox.tsx:43`, Today).

### P1-3 No single-key way to start a capture on the Inbox page
- Anchor: `InboxPage.tsx:111-118` (input focuses only when `captureRequested` is set), `Dashboard.tsx:112-116` (only the tray sets it), `Dashboard.tsx:149-153` (`q` opens the quick-create *task* dialog, not the capture field)
- Rubric: §1.5, §3.6
- Screens: light `.../inbox-light.png`, dark `.../inbox-dark.png`
- What's wrong: Capture is the page's primary action, yet from the list the only keyboard path to the field is Shift+Tab hunting. The `q` key that reads as "quick capture" opens a task dialog instead, and `Escape` inside the field does nothing (no blur back to the list).
- Fix: Bind `c` (or `/`) on the Inbox page to focus the input and `Escape` in the input to blur; list both in the help panel. Keep `q` as-is (locked: never remove a shortcut).

### P1-4 Add and convert are not optimistic, and the input locks while saving
- Anchor: `InboxPage.tsx:188-191` (await `create` then `setCaptures`), `:256` (`disabled={submitting}`), `:273` (`'...'` in the Save button), `:201-210` (await `convertToTask` then `refreshCaptures`)
- Rubric: §1.6 ("Captures: item appears in inbox immediately"), §3.6 (optimistic updates missing), §3.2 (friction)
- Screens: light `.../inbox-light.png`, dark `.../inbox-dark.png`
- What's wrong: The new row only appears after the round-trip, and the field is disabled during it, so rapid-fire capture (type, Enter, type) drops keystrokes. Converting waits for the server and a full re-fetch before the row leaves.
- Fix: Insert a temp row with a client id on Enter and reconcile on resolve (revert + toast on error); never disable the input; on convert, remove the row immediately and restore on failure. Frontend only.

### P1-5 "Loading..." text in the picker instead of a skeleton
- Anchor: `InboxPage.tsx:510`
- Rubric: §1.6 (skeleton placeholders matching content shape), §3.2
- Screens: light `.../inbox-movetodoc-light.png`, dark `.../inbox-movetodoc-dark.png` (loaded state; the text state is a first-frame flash)
- What's wrong: The doc list renders a centered "Loading..." string; the page itself already uses `Skeleton` rows (`:280-284`), so the picker is the odd one out.
- Fix: Three `Skeleton` rows `h-8 rounded-md` inside the same `.max-h-48` container.

### P2-1 Prefix routing exists in one of three capture entry points, with two vocabularies
- Anchor: `InboxPage.tsx:176-192` (routes via `capture_routes`: `/i`, `/q`, `/t`), `CommandBar.tsx:24-33` (`/task`, `/capture`, `/note`, `note:`, `idea:`, `remember` — `capture_routes` never consulted), `CommandBar.tsx:36-45` (default selection lands on a task match or "Create task", so "Save as note" needs an extra arrow press), `CaptureStrip.tsx:128-131` (saves verbatim, no parsing)
- Rubric: §2.3 (three entry points + prefix routing), §2.7 (bar infers intent), §1.2, §3.2 (multi-step where one step would do)
- Screens: light `.../inbox-route-pill-light.png`, dark `.../inbox-route-pill-dark.png` (pill only here; the bar and strip show nothing for the same text)
- What's wrong: `/i idea` routes to the Ideas doc from the inbox field, becomes a search for "/i idea" in ⌘K, and lands in the inbox as a plain note from the strip. Saving a note via ⌘K is ⌘K → type → ↓ → Enter unless the user remembers a second prefix set.
- Fix: Run every entry point through `parseRoutePrefix` + `dp.captureRoutes.route`, show the same pill in the bar and strip, and let a recognized route prefix select the matching action by default. `CROSS-SURFACE` (Shell: command bar; capture strip window).

### P2-2 Routed captures re-enter the inbox as triage work
- Anchor: `nimble-core/src/db/captures.rs:199-214` (every routed capture is re-inserted with `source='route'`, `routed_to=<label>`), `InboxPage.tsx:147-149` (list filters only `converted_to_task_id`), `:414-418` (renders the routed badge)
- Rubric: §2.3 (inbox is the mutable triage zone; a routed item is already processed), §1.2 (decision overhead)
- Screens: light `.../inbox-light.png`, dark `.../inbox-dark.png` (mock has no routed rows; the code path is unconditional)
- What's wrong: Typing `/i ...` saves to Ideas *and* adds a row to the inbox carrying an "Ideas" badge, so every routed thought must be triaged a second time.
- Fix: Filter `c.source !== 'route'` (or `!c.routed_to`) out of the triage list while keeping them searchable from ⌘K. Frontend only; `NEEDS RUST → queue for Marco` only if the history write itself should stop.

### P2-3 Three of the five intended per-item actions are missing; convert has no picker; dismiss has no undo
- Anchor: `InboxPage.tsx:420-436` (only "Move to doc" and "Convert to task"), `:201-210` (convert calls `convertToTask(id)` with no project/date/priority although the contract accepts `projectId` — `packages/types/src/data-provider.ts:103`), `CaptureDetailPage.tsx:141-149` (the only dismiss is a "Delete" in the detail view, immediate, no undo)
- Rubric: §2.3 (convert with picker, dismiss, defer, move to project, AI breakdown)
- Screens: light `.../inbox-row-hover-light.png`, dark `.../inbox-row-hover-dark.png`
- What's wrong: A note that should simply go away needs a click into detail, then Delete, with no way back. Defer, move-to-project and break-down all exist elsewhere in the app (`CommandBar.tsx:189-228`, `ProjectPickerMenu.tsx`) but not on the row.
- Fix: Add a row-level "Dismiss" with a 5s undo toast (re-create on undo), a "Move to project" using `ProjectPickerMenu` → `convertToTask(id, projectId)`, and "Break down" via `dp.ai.breakDownTask` + convert; keep one-click convert as the smart default (§1.2) and expose the picker as a secondary `⌥`-click. `NEEDS RUST → queue for Marco` for a true soft-delete if re-create is not acceptable for sync history.

### P2-4 Route hints are hardcoded in the placeholder and vanish once the user types
- Anchor: `InboxPage.tsx:255` (`"Write a note... (/i idea, /q quote, /t task)"`) vs `:70-75` (routes are fetched from Settings and can be anything — the mock has `/p Photo notes`, no `/q`)
- Rubric: §2.3 (prefix routing), §1.5 (shortcuts discoverable)
- Screens: light `.../inbox-light.png`, dark `.../inbox-dark.png`
- What's wrong: The only discoverability for routing is a placeholder that lies whenever routes are edited in Settings, and disappears at the first keystroke.
- Fix: Derive the placeholder from `routes` and, when the value starts with `/`, show the route list as chips under the field (or a small popover) until a prefix matches.

### P2-5 Empty state is flat and pushes an action

- Rubric: §1.1 (empty states are positive, "inbox zero" energy), §2.3 (positive empty state when cleared)
- Screens: light `.../inbox-empty-light.png`, dark `.../inbox-empty-dark.png`
- What's wrong: "Inbox is empty — nothing to process." reads as an absence, and the only element under it is an "Import from Obsidian" button that duplicates the header action and suggests the user should go get more.

### P2-6 Inbox rows and Tasks rows are two different components for the same task
- Anchor: `InboxPage.tsx:351-371` (task row: `h-9 px-2 rounded-md hover:bg-accent/30`, checkbox in-flow, no `PriorityBars`, no due date, no labels, dividers `divide-border/20`) vs `tasks/TaskItem.tsx:136-206` (`h-10`, `hover:bg-accent/20`, hover cluster hangs outside the column, `border-b border-secondary`, `ml-4 gap-3`, priority + labels + due)
- Rubric: §2.1 row anatomy (status, priority, title, project, due, source), §3.5 (row height 32–36: Inbox is 36, Tasks is 40 — one of them is off spec), cross-surface consistency
- Screens: light `.../inbox-light.png` vs `.../tasks-list-light.png`, dark `.../inbox-dark.png` vs `.../tasks-list-dark.png`
- What's wrong: The same `LocalTask` loses its priority bars and due date when viewed in the inbox, and the hover, gutter and border recipes differ, so the two lists don't read as one object.
- Fix: Render inbox task rows with `TaskItem` (`showGrip={false}`) and give `InboxNoteRow` the same gutter/hover/border recipe; pick one row height for both. `CROSS-SURFACE` (Tasks).

### P2-7 The capture field has no focus state and no accessible name
- Anchor: `InboxPage.tsx:248` (wrapper has no `focus-within` style), `:257` (`outline-none`, no `aria-label`)
- Rubric: §1.5 (keyboard-first)
- Screens: light `.../inbox-input-focus-light.png`, dark `.../inbox-input-focus-dark.png` (field is focused in both; nothing changes)
- What's wrong: Measured on focus: wrapper border stays `border/30`, no ring, no shadow, input outline `none`. On a page with 20+ focusable controls the user cannot tell the field is live. Screen readers get an unnamed textbox.
- Fix: `focus-within:border-ring/60` (or `focus-within:ring-1 ring-ring/40`) on the wrapper, `aria-label="Capture a note"` on the input.

### P2-8 Hardcoded `text-white` on the route pill fails contrast on two of three route colors

### P2-10 Capture strip uses off-token size and opacity values

### P3-1 `transition-all` and hardcoded durations bypass the motion tokens
- Anchor: `InboxPage.tsx:352`, `:390` (`transition-all duration-150`), `:481-482` (`animate-in fade-in … duration-200` — matches no token: 150/220/320)
- Rubric: §1.6 (ease-out motion) + craft principle "Never use `transition: all`" / "Transition only what changes"

### P3-2 Hit areas below the dense-desktop floor, nearly touching
- Anchor: `SelectionCheckbox.tsx:36` (16×16), `StatusDropdown.tsx:125-127` (`p-0`, 16×16), `InboxPage.tsx:421` (`gap-0.5` = 2px between two 18px-tall buttons), `:268-275` (bare text "Save" button)

- Screens: light `.../inbox-row-hover-light.png`, dark `.../inbox-row-hover-dark.png`

### P3-3 Picker radii are not concentric

### P3-4 Three icon sizes and a 2px stroke beside 400-weight text
