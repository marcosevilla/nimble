## Findings

### P1-1 Advertised j/k row navigation is dead on the Tasks page
- Anchor: `apps/desktop/src/hooks/useTaskNavigation.ts:10` (hook has **zero** call sites in `apps/desktop/src`); `apps/desktop/src/components/tasks/LocalTaskRow.tsx:165` (`focused` is threaded to `TaskItem` but no Tasks-page caller ever sets it); `apps/desktop/src/components/shared/HelpPanel.tsx:23-24` ("j / ↓ Next task", "k / ↑ Previous task" under *Tasks*).
- Rubric: §1.5 (every common action has a single-key shortcut; shortcuts discoverable via `?`), §3.6 (common action without a shortcut).
- Screens: light `tasks-focus-light.png`, dark `tasks-list-dark.png` (no focused-row state exists to capture).
- What's wrong: The Help panel promises j/k/x/Enter over the list, the hook implementing it exists and is gated to `currentPage === 'tasks'`, but nothing mounts it. Pressing j on Tasks does nothing; the `focused && 'bg-accent/10'` row style (`TaskItem.tsx:140`) is unreachable. The core keyboard-first promise fails on the library view.
- Fix: In `AllTasksView` and `ProjectDetailPage`, call `useTaskNavigation(visibleIds, { onOpen: openTask, onComplete: updateStatus('complete'), onSnooze: … })`, pass `focused={focusedIndex === i}` through `SectionedTaskList` → `LocalTaskRow`, and scroll the focused row into view. CROSS-SURFACE: Today (same hook, same dead `focused` prop).

### P1-2 Rows are mouse-only and the tab order lands on invisible controls
- Anchor: `apps/desktop/src/components/tasks/TaskItem.tsx:136-145` (root is `<div onClick={onOpen}>` — no `role`, `tabIndex`, or `onKeyDown`); `apps/desktop/src/components/shared/SelectionCheckbox.tsx:33-45` (a real `<button>` at `opacity-0` until hover — still focusable); `apps/desktop/src/components/tasks/StatusDropdown.tsx:124-140` (icon-only `PopoverTrigger`, no `aria-label`).
- Rubric: §1.5, §3.6 (Escape/keyboard gaps), Accessibility dimension (roles, labels, focus order).
- Screens: light `tasks-focus-light.png` (14 Tabs: focus alternates between a 16px status icon and an invisible checkbox — the list shows a ring on "Cull + edit Deftones" status only), dark `tasks-list-dark.png`.
- What's wrong: Recorded focus order from the page title: `Backlog` header → status icon (UA 3px outline) → *empty* button (the hidden checkbox, 1px outline on nothing) → status → hidden checkbox … The row body itself can never take focus, so Enter-to-open is impossible, and a screen reader hears an unnamed button for every status circle.
- Fix: Give the row `role="button" tabIndex={0}` with Enter/Space → `onOpen` (or make the title a `<button>`), set `tabIndex={-1}` on `SelectionCheckbox` while `autoHide` and not selected (reveal it with `group-focus-within:opacity-100`), and add `aria-label={\`Status: ${current.label}\`}` to the status trigger. CROSS-SURFACE: Today, Inbox (same `SelectionCheckbox`).

### P1-3 Past-due dates paint red and perform urgency
- Anchor: `apps/desktop/src/components/tasks/TaskItem.tsx:14,28` (`const overdue = isPast(parsed) && !isToday(parsed)` → `text-destructive`).
- Rubric: §1.1 (no "overdue" framing), §3.1 ("anything that performs urgency at the user"). Contradicts the surface's own no-guilt bucket at `lib/task-view.ts:49` ("Still open").
- Screens: light `tasks-list-light.png`, dark `tasks-list-dark.png` (9 of 15 rows show a red date; the detail subtask row in `tasks-detail-light.png` too).
- What's wrong: The word "overdue" is gone but its color is not. Red is the app's destructive token; on a library page whose header bucket says "Still open", nine red dates read as nine alarms. Measured 4.70:1 light / 4.18:1 dark — legible, which makes it louder.
- Fix: Drop the `overdue` branch; render every date `text-meta text-muted-foreground`, with `text-foreground` for Today only. Reserve `--destructive` for destructive actions. CROSS-SURFACE: Today (same `DueDateBadge`), detail subtask rows.

### P1-4 Every chip and action trigger strips its focus ring without a replacement
- Anchor: `apps/desktop/src/components/tasks/MetadataChips.tsx:63,66,126,161,231,292,353` (`outline-none` on CHIP_EMPTY / CHIP_PLUS / every filled-chip trigger); `apps/desktop/src/components/tasks/SelectionActionBar.tsx:27` (`ACTION_BUTTON`); `apps/desktop/src/components/detail/InlineTitle.tsx:50`; `apps/desktop/src/components/detail/TaskDetailPage.tsx:528` and `TaskComposerCard.tsx:206,220` (`focus-visible:ring-0`). Grep: 15 `outline-none` sites across `components/tasks` + `components/detail`, 0 `focus-visible:` additions.
- Rubric: §1.5 (keyboard-first), Accessibility dimension; craft: `better-ui` "Shadows for elevation, borders for structure — keep … focus states".
- Screens: light `tasks-detail-priority-light.png`, dark `tasks-detail-priority-dark.png` (chip row; tabbing to a chip produces no visible state in either theme).
- What's wrong: The design system already defines the ring (`ui/button.tsx:9`: `focus-visible:border-ring focus-visible:ring-3 focus-visible:ring-ring/50`) but the chip row, the selection bar and the inline title opt out. Keyboard users tab through Priority → Due → Labels → `+` blind.
- Fix: Executable now (token/focus fix, not structural): append `focus-visible:border-ring focus-visible:ring-3 focus-visible:ring-ring/50` to `CHIP_EMPTY`, `CHIP_FILLED`'s inner trigger, `CHIP_PLUS`, `ACTION_BUTTON`, and `InlineTitle`'s input; delete the `focus-visible:ring-0` overrides. CROSS-SURFACE: Inbox (composer chips via `QuickCreateDialog`).

### P1-6 Native `window.confirm` for discard and delete; delete has no undo
- Anchor: `apps/desktop/src/components/tasks/TaskComposerCard.tsx:158` ("Discard this task?" on Escape); `apps/desktop/src/components/detail/TaskDetailPage.tsx:358` ("Delete this task?"); `apps/desktop/src/components/tasks/SelectionActionBar.tsx:130`.
- Rubric: §3.2 (modal interruptions for trivial confirmations; multi-step where one-step works), §1.6 (instant feedback), Interaction dimension ("undo where destructive").
- Screens: not capturable in the harness (OS dialog); code-anchored.
- What's wrong: An un-themed macOS sheet interrupts Escape on a one-line draft, and the two deletes trade a confirm for an undo. The rest of the surface is optimistic (`SectionedTaskList.tsx:239-246` rolls back on failure); delete is the one action that asks first and offers nothing after.
