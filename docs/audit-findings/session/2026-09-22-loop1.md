## Findings

### P1-1 No reduced-motion handling — celebration is the heaviest motion in the app
- Anchor: `apps/desktop/src/components/focus/FocusCelebration.tsx:63-78` (18 confetti particles, `confetti-burst 800ms`), `:81` (`timer-glow` 1.5s), `:90` (`checkmark-draw` 600ms), `:96-111` (three staggered `animate-in` fades at 500/500/700ms), `:30-32` (sound on mount); keyframes at `apps/desktop/src/index.css:479-508`
- Rubric: §1.6 (ease-out, instant feedback — motion is decoration here, not feedback) + accessibility (reduced-motion)
- Screens: light `session-focus-celebration-light.png`, dark `session-focus-celebration-dark.png`
- What's wrong: `grep prefers-reduced-motion apps/desktop/src` → 0 hits; the only `motion-reduce:` utility in the codebase is `components/ui/button.tsx:9` (press scale). 25 `animate-in` sites across 14 files and 45 hardcoded `duration-*` sites run unconditionally. The celebration stacks five simultaneous motion layers plus a two-tone chime, with no opt-out.
- Fix: `CROSS-SURFACE` (every `animate-in` file: alert-dialog, popover, tooltip, dialog, select, dropdown-menu, SelectionActionBar, CommandBarResults, BriefDisplay, TaskDetailPage, InboxPage, FocusView, FocusBanner). One global rule in `index.css`: `@media (prefers-reduced-motion: reduce) { *, ::before, ::after { animation-duration: 0.01ms !important; animation-iteration-count: 1 !important; transition-duration: 0.01ms !important; } }`, and gate `playCompletionSound()` behind `matchMedia('(prefers-reduced-motion: reduce)')` until a sound setting exists (see P3-5).

### P1-2 Escape on the celebration starts the next task
- Anchor: `apps/desktop/src/components/focus/FocusCelebration.tsx:45-54` (Enter, Space, Escape all call `handleDismiss`), `apps/desktop/src/stores/focusStore.ts:199-209` (`dismissCelebration` → `startFocus(nextTask, …)` when a next task exists)
- Rubric: §3.6 (Escape doesn't return to previous state) + §2.4 (celebration "auto-surfaces" the next task — surfaces, not starts)
- Screens: light `session-focus-celebration-light.png`, dark `session-focus-celebration-dark.png`
- What's wrong: With a queue or `useFocusQueue` result present, every dismissal key — including Escape and a stray click anywhere on the overlay — commits the user to a new 25-minute session on a task they may not have read ("Next: …" is `text-meta` at 12px, muted). The 2.5s auto-dismiss (`:35-38`) does the same thing unattended. There is no path that shows the next task without starting it.
- Fix: Escape and click → `reset()` (end session, no next); Enter → start next; label the preview "Next: {task} — Enter to start"; keep auto-dismiss but have it land on the banner-collapsed next task paused, not running.

### P1-3 Complete, Stop and Minimize have no shortcuts; Escape is inert in the expanded view
- Anchor: `apps/desktop/src/components/layout/Dashboard.tsx:159-166` (only Space is bound for focus), `apps/desktop/src/components/focus/FocusView.tsx:162-200` (five buttons, none with a key hint), `apps/desktop/src/components/shared/HelpPanel.tsx:29-31` (Focus section lists one shortcut: Space)
- Rubric: §3.6 (a common action without a single-key shortcut) + §1.5
- Screens: light `session-focus-active-light.png`, dark `session-focus-active-dark.png`
- What's wrong: Verified live — with the session expanded, `Escape` left `isActive: true, isCompact: false`. Complete (the primary action, the only filled button on screen) is mouse-only. The celebration binds Enter/Space/Escape; the view that precedes it binds nothing but Space, so the two screens disagree about what the same keys do.
- Fix: In the Dashboard handler, when `focusActive && !isInput`: `Enter` → `completeFocus`, `Escape` → `setCompact(true)` (minimize, not stop), `Shift+Escape` or `s` → `abandonFocus`; render the keys as `<kbd>` hints on the buttons and add the rows to HelpPanel.

### P1-4 Green is hardcoded on every completion surface while `--success` sits unused
- Anchor: `apps/desktop/src/components/focus/FocusView.tsx:116` (`text-green-500`), `:131` (`bg-green-500`), `:151-152` (`bg-green-500/10`, `text-green-600 dark:text-green-400`), `:174` (`bg-green-600 hover:bg-green-700 text-white` overriding the Button variant); `FocusCelebration.tsx:82` (`text-green-500`), `:18` (six raw hex confetti colors); `FocusBanner.tsx:36` (`text-orange-500` on break)
- Rubric: §3.4 (hardcoded colors instead of frame theme vars) + §1.4 (color for semantic meaning, via tokens)
- Screens: light `session-focus-active-light.png`, dark `session-focus-active-dark.png`
- What's wrong: `themes.css:29` and `:68` define `--success` per theme (light `oklch(0.62 0.14 145)`, dark `oklch(0.70 0.16 150)`); it is referenced twice in `src`. `text-green-500` is referenced 17 times. The Complete button measures `oklch(0.627 0.194 149)` — a Tailwind primitive, not the token, so it will not follow the warm theme or any future accent theme. The confetti hexes are Tailwind's cool-blue/pink/violet 500s on a warm palette.
- Fix: `CROSS-SURFACE` (Tasks, Today, Goals share the `text-green-500` pattern). Swap to `text-success` / `bg-success` / `text-success-fg`; give Button a `success` variant so `:174` stops overriding classes; derive confetti colors from `var(--success)`, `var(--accent-blue)`, `var(--foreground)` at three opacities.

### P1-5 Activity timeline paints 42 action types with 8 raw hues
- Anchor: `apps/desktop/src/components/activity/ActivityTimeline.tsx:21-64` (`ACTION_META.color`: `text-green-500`, `text-orange-500`, `text-red-500`, `text-indigo-500`, `text-purple-500`, `text-amber-500`, `text-teal-500`, `text-accent-blue`)
- Rubric: §1.4 (color reserved for semantic meaning: status, priority, source, health) + §3.4 (hardcoded colors)

- Fix: `CROSS-SURFACE` (`TaskActivityLog.tsx`). Collapse to four semantic colors — `text-success` (created/completed), `text-destructive` (deleted), `text-accent-blue` (focus, moves), `text-muted-foreground` (everything else) — and export one `ACTION_META` from a shared module.

### P2-1 Navigation is locked while a session is expanded
- Anchor: `apps/desktop/src/components/layout/Dashboard.tsx:217-218` (`focusActive && !focusCompact ? <FocusView />` takes precedence over `<PageContent page={currentPage} />` regardless of page); `apps/desktop/src/components/layout/NavSidebar.tsx` (no focus awareness — `grep -n focus` → 0 hits)
- Rubric: §2.4 ("Pomodoro-style focus session that doesn't lock navigation")
- Screens: light `session-focus-active-light.png` (nav sidebar rendered, inert), dark `session-focus-active-dark.png`
- What's wrong: Verified live — pressing `1` set `currentPage` to `today` and the timer stayed on screen. The sidebar highlights the new page while the content does not change; the only way out is the 17px-tall "Minimize" text button (P3-3).
- Fix: In the `currentPage` effect (`Dashboard.tsx:~100`), if `useFocusStore.getState().isActive && !isCompact` → `setCompact(true)`. Navigation then collapses the session to the banner, which is what the banner exists for.

### P2-2 Break view says "Round 0 of 2 complete"

### P2-6 Motion durations and curves bypass the tokens
- Anchor: `FocusView.tsx:87,108,151` (`duration-300` ×3), `FocusBanner.tsx:31` (`duration-200`), `FocusCelebration.tsx:58,96,102,109` (`duration-200/500/500/700`), `FocusCelebration.tsx:72` (`800ms cubic-bezier(0.22, 1, 0.36, 1)`), `index.css:493` (`600ms cubic-bezier(0.22, 1, 0.36, 1)`), `index.css:503` (`1.5s ease-in-out`), `SessionPage.tsx:126` (`transition-transform`, no duration/ease)
- Rubric: §1.4 (restraint, one motion language) — the brief lists token-bypassing durations as findings
- Screens: light `session-focus-active-light.png`, dark `session-focus-active-dark.png`
- What's wrong: `--transition-fast/base/slow` (150/220/320ms) and `--ease-entrance/exit` exist at `index.css:99-107`; none of the eleven sites above use them. - Fix: `duration-[var(--transition-base)] ease-[var(--ease-entrance)]` for entrances; celebration stagger at base/base+100/base+200; confetti/checkmark keyframes take `var(--ease-entrance)`.
