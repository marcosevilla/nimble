# Cross-cutting — Loop 1 audit (2026-09-22)

**Question:** what would make Nimble feel like one designed object rather than seven pages, and what is the smallest set of changes that gets there?

Files audited (composition layer only): `apps/desktop/src/components/layout/Dashboard.tsx`, `NavSidebar.tsx`, `RightSidebar.tsx`, `components/shared/PageHeader.tsx`, `PageDragRegion.tsx`, `CollapsibleSection.tsx`, `typography.tsx`, `components/ui/card.tsx`, the frame of each page in `components/pages/*.tsx`, `components/tasks/TaskListHeader.tsx`, `ProjectDetailPage.tsx`, `components/detail/TaskDetailPage.tsx` (frame only), `components/docs/DocEditor.tsx` (frame only), `index.css`, `themes.css` (warm only).
Screenshots: all 24 in `docs/audit-findings/screenshots/loop1-before/` (light + dark per surface). No new shots taken.

Rubric: `docs/ux-intent.md` §1.4 (restrained, earned attention, 8px grid, density 15–25), §1.6 (ease-out, one feedback motion), §3.4 (type/hardcoded colors), §3.5 (density/spacing).

---

## Short answer

Nimble already has the *materials* of one object — one palette, one type scale, one motion-token set, one `PageHeader`. What it lacks is a single **frame** that every page is forced through. Today each page composes its own header, its own content width, its own gutter, its own card recipe, its own empty state and its own entrance. Seven pages × five independent choices is what reads as "seven pages". The fix is not new design; it is four primitives that remove the choice.

## Axis 2 — Surface hierarchy

There is no single elevation story; there are **eight card recipes** and **eight border alphas** in play:

- ui `Card`: `rounded-xl bg-card ring-1 ring-foreground/10` (`card.tsx:15`) — Goals only.
- `rounded-lg border bg-card p-4` — `PrioritiesSection.tsx:252`, `SessionPage.tsx:119`.
- `rounded-lg border border-border p-4`, **no bg** — `ReminderCatchUp.tsx:32`.
- `rounded-xl border border-border/30 bg-muted/30 p-4` — Today brief `TodayPage.tsx:332`; Inbox input strip `InboxPage.tsx:248` (`h-10`).
- `ReviewStep`: `rounded-xl border bg-card` active / `bg-muted/30 border-border/30` inactive (`TodayPage.tsx:80-81`).
- Popovers: `rounded-xl border border-border/30 bg-popover shadow-xl` (`HelpPanel.tsx:202`, `InboxPage.tsx:482`) vs `border-border/50 … shadow-lg shadow-black/10` (`CommandBar.tsx:304`).
- Rails: `NavSidebar.tsx:277` `border-r border-secondary bg-sidebar`; `ProjectSidebar.tsx:204` `border-r border-border/20 bg-sidebar`; `FolderTree.tsx:151` `border-r border-border/20 bg-muted/10`; `RightSidebar.tsx:54` `border-l border-secondary bg-background`. Four rails, four recipes.

Grep counts (`components/`, excluding nothing): `border-border/20` ×27, `/30` ×21, solid ×18, `/50` ×4, `/40` ×3, `/10` ×3, `/60` ×2, `/5` ×2. `shadow-md` ×7, `shadow-lg` ×7, `shadow-xl` ×3, `shadow-sm` ×3, `shadow-2xl` ×1.

Two token-level causes:
1. **Dark borders vanish.** `themes.css:54` sets dark `--border: oklch(1 0 0 / 8%)`. `border-border/20` multiplies that to ~1.6% alpha — invisible. That is why the Today brief card and Inbox strip have no visible edge in `today-dashboard-dark.png` / `inbox-dark.png` but do in light. The opacity modifiers were tuned against the light `--border` (an opaque gray) and silently break in dark.
2. **Light card is invisible.** `--card: oklch(1 0 0)` on `--background: oklch(0.995 0.003 75)` (`themes.css` warm lines 2-4) is a 0.5% lightness step; light cards depend entirely on their border. In dark (`0.19` on `0.14`) the card reads as a fill. The two themes therefore have *different* elevation logics: light = outlined, dark = filled.
3. **Sidebar tokens are not warm.** `--sidebar: oklch(0.985 0 0)`, `--sidebar-border: oklch(0.922 0 0)` (light, `themes.css` warm 29-36) and `--sidebar: oklch(0.205 0 0)`, `--sidebar-primary: oklch(0.488 0.243 264.376)` (dark, 65-72) are shadcn defaults — achromatic, plus a saturated blue primary. The nav rail is the only neutral-gray surface on a warm page (`tasks-list-dark.png`, left rail vs content).

Rubric: §1.4 (earned attention, restraint), §3.4 (hardcoded colors), craft principle "Shadows for elevation, borders for structure".

## Axis 3 — Type voice

Tokens are used almost everywhere (the scale is real and the Tuner works). The inconsistency is *which* token a role gets:

- **Page title:** `text-title` on six pages (`PageHeader.tsx:47`) vs `text-display` on Tasks (`TaskListHeader.tsx:209`) and task detail (`TaskDetailPage.tsx:486`). **Tasks is the outlier** — `tasks-list-light.png` shows a 20px "Tasks" 30px below a blank header band while every other page has a 15px title in the band.
- **Section title:** `text-body-strong` (Today, Tasks groups, Habits, Priorities) vs `text-label text-muted-foreground` (Activity `ActivityTimeline.tsx:219`, Docs `DocEditor.tsx:149`, rail headers `FolderTree.tsx:156` / `ProjectSidebar.tsx:209`) vs `text-title` (Settings `SettingsPage.tsx:188`). The `SectionTitle` primitive in `typography.tsx:101-107` is `text-title` and only Settings uses it — so the primitive that exists is the one nobody else adopted.
- **Row title / meta:** consistent — `text-body` + `text-meta text-muted-foreground` on Tasks, Inbox, Today, Activity. Not an issue.
- **Greeting:** `text-title` (`TodayPage.tsx:194`, `:313`) — same token, same weight, same size as the page title 40px above it. Two headings, no hierarchy.
- Off-scale stragglers: `text-white` on the route pill (`InboxPage.tsx:162`), `font-semibold` inline (`PrioritiesSection.tsx:60`, `SessionPage.tsx:32`), `font-bold` (`HabitsSection.tsx:168`). Rubric §3.4.

## Axis 4 — Color discipline (§1.4)

Semantic color is mostly honest (status circles, label dots, life-area bars, accent swatches are all data). Decorative or over-loud uses:

- **Loudest page: Tasks.** Nine red dates in `tasks-list-light.png` / `-dark.png`. Anchor: `TaskItem.tsx:28` `overdue ? 'text-destructive' : 'text-muted-foreground'`. The word is neutral ("Aug 1") but the color performs urgency at the user — nine times in one viewport. §1.1 / §3.1 by spirit, §1.4 by letter. Goals is second (four saturated bars + four dots + four pills, `GoalsPage.tsx:52-115`) but each color *is* meaning.
- Activity icon colors use raw Tailwind palette, not tokens: `text-amber-500`, `text-red-500` (`ActivityTimeline.tsx:25-61`, 12 sites). §3.4.
- `Sparkles` icon is `text-accent-blue` as AI flavor (`PrioritiesSection.tsx:145`, `:214`) — decoration; `FocusBanner.tsx:31` `bg-accent-blue/5`; `FocusView.tsx:151` `bg-green-500/10`. Decoration.
- Calendar now-line `#de1f1f` (`CalendarPanel.tsx:162-163`) is a documented exception; it is the most saturated pixel on every page that shows the rail. Noted, not re-litigated.
- Selected rows tint `bg-accent-blue/10` (`InboxPage.tsx:283`, `:353`) while nav-active is `bg-accent/60` (`NavSidebar.tsx:67`) — two "selected" colors.
- 50 hex literals outside `components/ui/` (mostly data-color pickers in Goals/Settings/Habits — acceptable — plus `CalendarPanel`, `FocusCelebration`).

## Axis 5 — Motion (§1.6)

- **Page switch has no entrance at all.** `Dashboard.tsx:232-235` `<main key={currentPage}>` carries no animation class; pages cut. (The `useLayoutEffect` comment at `:91-93` references an entrance animation that no longer exists.)
- **Panels have five different entrances.** Four bespoke keyframes in `index.css` — `help-panel-in` (8px, 0.95), `capture-strip-in` (−4px, 0.98, blur), `bulk-bar-in` (12px, 0.95), `command-flyout` (40px, 0.92, blur) — plus tw-animate presets at four more offsets: `slide-in-from-bottom-2` (`SelectionActionBar.tsx:150`), `-bottom-3` (`InboxPage.tsx:482`), `-top-1` (`CommandBarResults.tsx:77`, `BriefDisplay.tsx:69`), `-top` (`FocusBanner.tsx:31`).
- **45 literal durations bypass the tokens:** `duration-150` ×16, `-100` ×8, `-300` ×7, `-500` ×6, `-200` ×6, `-700`, `-1000`. `RightSidebar.tsx:54` uses a raw `ease-[cubic-bezier(0.22,1,0.36,1)]` that is not `--ease-entrance` (`0.16,1,0.3,1`). `transition-all` appears on `NavSidebar.tsx:65`, `InboxPage.tsx:282`, `GoalsPage.tsx:59`, `HabitsSection.tsx:138` (craft principle 14).
- No `prefers-reduced-motion` guard anywhere in `index.css`.

## (a) System moves — ranked by impact ÷ effort

### 1. One `PageFrame` — header + width + gutter, adopted by all seven pages
**What:** `components/shared/PageFrame.tsx` (~60 lines) = `PageHeader` (kept as-is: sticky, drag region, `title / meta / actions / secondary`) + a scroll body that renders one content column: `mx-auto w-full max-w-[640px] px-6 py-6`, with `width="wide"` (768) for Settings and the Doc editor. Skeleton state goes through the same frame so the header never flickers.
**Touches:** `TodayPage.tsx:89-91, 209-210, 320-321` (three header+body pairs → one; delete the second `text-title` greeting or drop it to `text-body-strong`), `InboxPage.tsx:132-147`, `GoalsPage.tsx:404, 499`, `SessionPage.tsx:261-263` (adds the missing `mx-auto`), `SettingsPage.tsx:1275-1276`, `DocsPage.tsx:50-55` + `DocEditor.tsx:116`, `TasksPage.tsx:69-75, 203-212` + `ProjectDetailPage.tsx:130-134` (replace `PageDragRegion` + scrolling `text-display` with `PageHeader title` and move the sort/filter triggers into `actions`), `TaskDetailPage.tsx:418` (`pt-[30px]` → frame). `PageDragRegion.tsx` becomes unused.
**Size:** +60 new, ~120 lines touched, 9 files. **Impact:** removes 5 widths → 2, 4 gutters → 1, 2 title sizes → 1, the Today double-title, and the Tasks header flicker. This is the single change that makes the seven screenshots line up.

### 2. One surface token set — three tiers, warm rails, dark-safe borders
**What:** in `index.css` add three utilities: `surface-panel` (`rounded-lg border border-border bg-card`), `surface-inset` (`rounded-lg bg-muted/40`, no border — input strips, brief accordion, inactive review step), `surface-popover` (`rounded-xl border border-border bg-popover shadow-lg shadow-black/10`). In `themes.css` warm: set `--sidebar` / `--sidebar-border` / `--sidebar-accent` to the warm `--muted` / `--border` / `--accent` values in both modes; delete the blue `--sidebar-primary`; raise dark `--border` from 8% to 12% and **retire the `/20`–`/30` modifiers on `border-border`** (48 sites → plain `border-border`) so light and dark share one edge strength. Nudge light `--card` to `oklch(1 0 0)` → keep, but give `surface-panel` a `shadow-sm`-class layered shadow only in light so elevation logic matches dark's fill.
**Touches:** `index.css` (+25), `themes.css` (~12 lines), `card.tsx:15`, `PrioritiesSection.tsx:252`, `SessionPage.tsx:119`, `ReminderCatchUp.tsx:32`, `TodayPage.tsx:80-81, 332`, `InboxPage.tsx:248, 482`, `HelpPanel.tsx:202`, `CommandBar.tsx:304`, `NavSidebar.tsx:277`, `ProjectSidebar.tsx:204`, `FolderTree.tsx:151`, `RightSidebar.tsx:54`; then a mechanical `border-border/(20|30)` → `border-border` sweep.
**Size:** ~40 new, ~65 one-line swaps. **Impact:** eight card recipes → three; four rails → one; dark borders become visible; nav rail stops being the only cool-gray surface.

### 3. One `SectionTitle` + one `EmptyState` primitive
**What:** redefine `typography.tsx` `SectionTitle` as `text-body-strong text-foreground` with optional `count` (`text-meta text-muted-foreground`) and `action` slot; `CollapsibleSection` renders it. Settings keeps `text-title` via an explicit `size="lg"` (its sections are pages-within-a-page, the only justified exception). Add `components/shared/EmptyState.tsx` (~30 lines): centered, `py-12`, optional lucide icon at `text-muted-foreground`, one `text-body text-muted-foreground` line, optional `<kbd>` hint or one `Button`.
**Touches:** `typography.tsx:97-107`, `CollapsibleSection.tsx:39-48`, `ActivityTimeline.tsx:219-227`, `DocEditor.tsx:149`, `FolderTree.tsx:156`, `ProjectSidebar.tsx:209`, `PrioritiesSection.tsx:215`, `HabitsSection.tsx:372, 396`, `TaskDetailPage` "Subtask"/"Reminder" headings; empty states at `TasksPage.tsx:87-95`, `ProjectDetailPage.tsx:146-148`, `GoalsPage.tsx:502-522`, `InboxPage.tsx:187-189`, `ActivityTimeline.tsx:206-210`, `SessionPage.tsx:233-237`, `DocEditor.tsx:106-108`, `TodayPage.tsx:337`.
**Size:** +45 new, ~50 touched. **Impact:** 4 section-title styles → 1 (+1 named exception); 7 empty-state recipes → 1, all positive-framed (§1.1).

### 4. One entrance — page fade + one panel keyframe + tokenized durations
**What:** add `.page-enter` (`opacity 0→1, translateY(4px)→0`, `var(--transition-base) var(--ease-entrance)`) and apply to `<main key={currentPage}>` (`Dashboard.tsx:234`) — one orchestrated moment per navigation, nothing staggered. Collapse `help-panel-in`, `capture-strip-in`, `bulk-bar-in`, `command-flyout` into one `panel-in` (8px, 0.98, no blur) and point the four classes at it; swap the four tw-animate `slide-in-from-*` presets to the same class. Replace `duration-{100,150,200,300,500}` literals with `duration-(--transition-fast|base|slow)`; `RightSidebar.tsx:54` easing → `ease-(--ease-entrance)`; four `transition-all` → explicit properties. Wrap all keyframes in a `@media (prefers-reduced-motion: reduce)` reset.
**Touches:** `index.css:236-275, 436-476` (~20 lines net), `Dashboard.tsx:234`, ~45 duration swaps across ~25 files (mechanical), 4 `transition-all` sites.
**Size:** ~20 CSS, ~55 one-token swaps. **Impact:** 9 entrance recipes → 2 (page, panel); every duration reads a token; reduced-motion honored.

**Not a system move, but one line worth a decision:** `TaskItem.tsx:28` past-due `text-destructive` → `text-foreground`. Turns nine red dates in the Tasks viewport into nine neutral ones (§1.1). One line; flagged because it is a policy change, not a polish change.

## (c) The target feel

Every page opens the same way: a 40px band with a 15px Geist title at the left edge and, at most, a count and one or two quiet actions at the right; the band stays put while content scrolls under it. Beneath it, one 640px column sits centered in the pane with 24px of air on every side — Settings and the document editor are the only surfaces allowed to widen to 768 — so the eye lands in the same place on Today, Inbox, Goals and Activity, and switching pages feels like turning a page in the same notebook, with a 220ms settle rather than a cut. Inside the column there are exactly three kinds of surface: the page itself, a panel (one border weight, one radius, visible in dark), and a popover that floats with one shadow. Section headings are the same 13px medium wherever they appear, followed by a dimmer count; empty sections say one calm sentence in the middle of the column. Color happens only where a status circle, a label dot or a life-area bar is telling you something; dates, icons and chrome stay in warm gray, including the left rail, which is the same warm gray as everything else. The result is that a screenshot of any page, cropped to remove its content, is indistinguishable from any other — which is what "one designed object" means in practice.
